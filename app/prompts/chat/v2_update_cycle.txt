Change the work rotation, its anchor, or shift it by days. Every change applies immediately.
- Handle "off by one day" scenarios with shift_by_days. A positive number means each shift happens that many days later. A negative number means each shift happens that many days earlier.

A ROTATION CHANGE (the default) starts on a date and leaves earlier days alone:
- "From Monday I'm on 2-2-3", "my roster changes next month", "starting today I work 7 on 7 off".
- Send effective_from with the first date of the new rotation. Without one, it starts today.
- Send anchor_date and anchor_cycle_day for the new rotation. If the user did not say which day of the new cycle the start date is, use effective_from as day 1 and say so.
- Days before effective_from keep the shifts they were worked on.

A CORRECTION replaces the rotation for every date, past included:
- Only when the user says the saved rotation or anchor was wrong: "that was a mistake", "I set it up wrong", "it was always 5 on 5 off".
- Send correction=true and no effective_from.
- A correction fixes the current rotation and keeps earlier roster changes. When the user says it was ALWAYS this rotation, from the very start ("it's always been 5 on 5 off"), also send whole_calendar=true.

ROTATION ANCHOR vs EMPLOYMENT START:
- The anchor_date is when the user's STABLE ROTATION began, not their employment start date
- Days before the anchor stay filled from the pattern. Do not mark them blank unless the user explicitly asks
